# 날짜 지정 이상치 알림 시뮬레이션

기존 매출·뉴스·영상은 그대로 두고 실행별 기준 날짜만 하루씩 진행합니다.
자동 타이머는 사용하지 않으므로 무료 Render 휴면 중에 임의로 발송하지 않습니다.

## Slack 홈에서 사용

1. 봇의 홈 → **날짜 지정 시뮬레이션**.
2. 시작일·종료일과 대상(3사 모두 / CU / GS25 / 세븐일레븐) 선택.
3. **기간 미리보기**: 이상치 날짜·브랜드·편차 확인. DB 기록과 Slack 발송 없음.
4. **새 실행 만들기**: 기간·대상·알림 채널·임계값을 실행에 고정해 저장. 발송 없음.
5. **하루 진행 · 알림 전송**: 다음 날짜 한 날만 검사하고 이상치가 있으면 전송.
6. 다음 날을 진행하거나 **현재 상태 새로고침**으로 진행률·발송 이력을 확인.

새 실행은 마지막 실행을 덮어쓰거나 이력을 삭제하지 않습니다.
같은 기간으로 새 실행을 만들면 별도 시연으로 취급하므로 알림이 다시 나갈 수 있습니다.
진행 중 날짜 입력을 바꿔도 기존 실행의 고정 기간은 바뀌지 않습니다.
홈을 닫았다가 다시 열거나 서버가 재시작되어도 본인 실행을 DB에서 다시 조회합니다.

기본 시연은 **2024-11-20~2024-11-22 / 3사 모두**입니다.

| 날짜 | 기존 기준의 예상 알림 |
|---|---|
| 2024-11-20 | CU 급감, GS25 급등 |
| 2024-11-21 | CU 급등, GS25 급감 |
| 2024-11-22 | 없음 (발송 없이 날짜 진행) |

모든 알림에 `[시뮬레이션 · 실행ID]`를 붙입니다. 기본 전송 대상은 기존
`SLACK_CHANNEL_ALERT`이며, 별도 시연 채널을 쓰려면 `SLACK_CHANNEL_SIMULATION`을
지정하고 그 채널에 봇을 초대합니다. 실행 생성 시점의 채널은 변경하지 않습니다.

## 판정과 화면 범위

- [기존 고정 기준](anomaly_method.md)을 사용합니다. 실행 생성 시 임계값을 JSON으로 보존합니다.
- 첫날 편차 결측은 이상으로 판정하지 않습니다. 누락·중복 날짜가 있으면 미리보기에서 거부합니다.
- 마지막 완료일까지의 그래프만 홈에 표시합니다.
- 알림·실행 화면의 대시보드 URL에는 `as_of`를 넣어 이후 날짜를 표시하지 않습니다.
  정상 대시보드 URL은 계속 전체 기간을 조회할 수 있습니다.
- 기준 자체는 2024년 전체로 산출했으므로 회고적 재현이며, 미래 정보를 배제한 성능 평가는 아닙니다.
- 미리보기는 실행 전 전체 계획을 확인하는 기능이므로 선택한 전체 기간의 예상 결과를 보여줍니다.

## 실행·중복·장애 처리

`simulation.runs`에 소유자·고정 기간·대상·채널·임계값·다음 날짜·진행 상태를,
`simulation.events`에 날짜·브랜드·편차·발송 상태와 Slack 메시지 식별자를 저장합니다.
`all_sale` 및 기존 콘텐츠 테이블에는 쓰지 않습니다.

- 소유자 조건과 실행 행 잠금으로 다른 사용자의 실행 및 동시 진행을 차단합니다.
- 버튼의 예상 날짜와 DB의 다음 날짜를 비교하므로 더블클릭·이전 화면의 버튼으로 이틀을 진행하지 않습니다.
- 실행·날짜·브랜드 조합에 UNIQUE 제약을 둡니다.
- 전송 예약을 먼저 커밋하고 Slack 성공 응답 후 발송 완료를 기록합니다.
- 전송 요청에는 앱의 재시도 비활성 클라이언트를 사용하며 같은 채널의 연속 발송은 간격을 둡니다.
- 타임아웃 또는 성공 응답 이후 DB 장애는 발송 여부가 불명확할 수 있습니다.
  이 경우 ‘확인 필요’로 멈추고 **자동 재발송하지 않습니다**. 정확히 한 번 전달을 보장한다는 뜻은 아닙니다.
- 서버 중단으로 `processing` 상태가 남으면 5분 후 조회 시 확인 대상으로 전환합니다.
  새 실행 전에 실제 채널의 메시지·기록을 확인해야 합니다. 확인 대상 실행을 자동 재개하는 기능은 없습니다.

## 최초 테이블 준비

대상 Aiven PostgreSQL 연결 설정을 갖춘 프로젝트 루트에서 한 번 실행합니다.
부팅·모듈 import·홈 방문은 테이블을 자동 생성하지 않습니다.

```powershell
.\.venv\Scripts\python.exe -m cv_store.simulation.setup
```

실행하는 SQL은 `database/schema/simulation.sql`이며 별도 `simulation` 스키마만 생성합니다.
기존 DB 사용자를 임의로 바꾸거나 원본 테이블을 재생성하지 않습니다.

## 로컬 미리보기만 실행

```powershell
.\.venv\Scripts\python.exe -m cv_store.jobs.simulate_sales --start 2024-11-20 --end 2024-11-22
.\.venv\Scripts\python.exe -m cv_store.jobs.simulate_sales --start 2024-11-21 --end 2024-11-21 --store CU
```

CLI는 조회·미리보기만 지원합니다. 실제 발송·진행은 Slack 홈의 버튼으로 수행합니다.

## 검증

합성 자료로 경계 포함·누락/중복 날짜, 발송 전 예약 순서, 조용한 날의 진행,
중복·오래된 버튼, 불명확한 요청의 재시도 방지, 기준일 이후 대시보드 차단을 확인합니다.
실제 PostgreSQL에서 소유자 격리·UNIQUE 제약·진행/완료를 검증한 행은 롤백했습니다.
실제 기간 미리보기는 위 3일의 4건과 일치합니다. 실발송·Slack 조작은 배포 후 별도로 확인합니다.
