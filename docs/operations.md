# 운영 준비와 미확인 사항

## 현재 DB 상태

로컬 MariaDB의 스키마를 확인해 Aiven PostgreSQL로 복사했습니다. 원본은 읽기 전용으로 유지했고,
모든 행의 해시와 별도 애플리케이션 조회를 검증했습니다. 연결은 SSL 및 CA/호스트 검증을 사용합니다.
상세 내용은 [PostgreSQL 설정 문서](postgresql_setup.md)에 기록했습니다.
아래 구조 정리 단계의 기록과 별개로 DB 이전이 완료됐으며 서버·Slack·Tableau는 후속 작업입니다.

## 초기 구조 정리의 범위

- 소스·데이터·실험 분리, 파일 이름 정리, 공통 설정, 로컬 회귀 테스트.
- 서버·DB·Slack 앱을 생성하지 않음. DB/Slack/수집 사이트와 실제 통신하지 않음.
- 원본 데이터·체크포인트의 내용 유지 및 Git 업로드 제외.
- 공개 Git 이력은 민감정보가 담긴 과거 커밋과 연결하지 않는 정리본 기준으로 게시.

## 향후 환경 준비 순서

1. 보존된 로컬 DB의 스키마·뷰·테이블·인덱스를 읽기 전용으로 확인.
2. `sale`·성별 매출·행사·검색 트렌드와 `all_sale` 관계, 편차 산출 SQL 확인.
3. 뉴스·유튜브 데이터와 날짜·브랜드 형식 확인. 빠진 수집·적재 코드 복구.
4. 데이터 제공·공개 조건을 확인하고 로컬 DB 백업 확보.
5. 필요하면 새 서버와 DB를 별도 구축. 이 저장소에는 생성 자동화 없음.
6. 본인 소유 Slack 앱·워크스페이스·채널을 준비하고 환경변수 설정.
7. 작은 검증 범위에서 실제 DB 조회·알림·행사 수집을 순서대로 확인.
8. Tableau 워크북·데이터 연결·새로고침 방식 확인 후 재연결.
9. 전체 데이터 적재 완료 후 조회 기준 날짜를 사용하는 시뮬레이션 재설계.

## 설정

`.env.example`은 변수 목록입니다. DB 연결 시 프로젝트 루트 `.env`를 자동으로 읽고,
이미 지정된 프로세스 환경변수는 덮어쓰지 않습니다.

- DB: `DB_ENGINE`, `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`.
- PostgreSQL SSL: `DB_SSLMODE=verify-full`, `DB_SSLROOTCERT`에 Aiven CA 인증서 경로.
- 이전 원본 MariaDB: `SOURCE_DB_*`. 대상 DB와 접속 설정을 분리하고 읽기 전용으로 점검.
- Slack: `SLACK_BOT_TOKEN`, `SLACK_APP_TOKEN`, 기능별 `SLACK_CHANNEL_*`.
- Tableau: `TABLEAU_DASHBOARD_URL`, `TABLEAU_TP_URL`.
- Selenium: 선택적 `CHROMEDRIVER_PATH` 및 설치된 Chrome.

봇은 Socket Mode 기반입니다. 예전 팀원의 앱 ID·채널 ID·토큰은 재사용하지 않습니다.
실행 시 제공된 토큰으로 인증 동작이 발생할 수 있으므로 이번 정리에서는 앱 팩토리도 실제로 호출하지 않았습니다.
채널별 멘션 및 `show_more_ytb`·`show_more_news` 액션에 맞는 새 앱 설정은 후속 작업입니다.

기존 인증 문자열은 보관한 텍스트에서도 가렸지만 이전 Git 커밋에는 남아 있을 수 있습니다.
당시 토큰·DB 비밀번호가 유효하다면 소유자 측에서 폐기·재발급해야 합니다.
공개 브랜치의 이전 이력은 정리본과 분리합니다. 새 서버·DB·Slack을 만들더라도 예전 자격 증명이
자동으로 폐기되지는 않습니다. 현재 파일의 인증 값은 제거했으며, 과거 설정이 남을 수 있는 `.pyc` 8개도 삭제했습니다.
GitHub의 과거 커밋 캐시와 기존 복제본은 브랜치 이력 교체만으로 삭제되지 않습니다.
잔존 캐시 제거는 [GitHub의 민감정보 제거 안내](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)에 따라 별도 처리해야 합니다.

## 실행과 시뮬레이션

현재 조회 봇을 시작해도 날짜가 자동으로 진행되거나 과거 알림이 전송되지 않습니다.
`jobs.anomaly_alerts --date`는 지정 날짜의 명시적 1회 발송이며 재실행 시 중복 전송될 수 있습니다.
알림 발송 이력·재시작 복원·전체 기간 재생 UI는 후속 시뮬레이션 설계 범위입니다.

과거 일별 매출 및 트렌드 적재·날짜 체크포인트는 `archive/simulation/`에만 있습니다.
현재 적재 명령은 선택적 복구 도구이며 일반 서비스 실행에 필요하지 않습니다.
`--write` 없이는 DB 연결을 하지 않으며 로컬 파일 전체를 검증합니다.
원본 파일·체크포인트는 Git 제외 대상이므로 새 체크아웃에 없을 수 있습니다.

행사 예약 실행은 `--daily`를 명시할 때만 시작합니다. 기존 실제 설정값을 유지했습니다.

| 작업 | 시각 |
|---|---|
| CU | 13:22 |
| GS25 | 11:30 |
| Seven | 00:00 |
| 증정 상품 | 11:49 |

호스트 현지 시간 기준입니다. 운영 시간대·재시도·프로세스 감독·중복 실행 방지는 배포 전에 정해야 합니다.

## 수집기의 남은 제약

- 실제 사이트 DOM은 이번에 접속하지 않아 selector 유효성을 검증하지 않았습니다.
- CU는 기존 CU `idx`가 필요하고 행사 기간을 실행일~월말로 만드는 과거 규칙이 남아 있습니다.
- GS25 활성 버전은 첫 페이지 수집입니다. 페이지 이동 버전은 `archive/collectors/`에 보존했습니다.
- Seven은 원래의 이벤트 기간 문자열 형식을 기대합니다. 개별 이벤트 실패 후 화면 복귀는 추가 검증 대상입니다.
- 증정 상품은 최신 날짜를 기준으로 종료하므로 같은 날짜에 뒤늦게 추가된 상품은 놓칠 수 있습니다.
- 네트워크 재시도·최대 페이지·수집 지표·중복 제약·모든 예외 경로의 자원 정리는 추가 점검 대상입니다.
- 현재 확인된 오류인 CU의 타 브랜드 `idx` 혼합과 증정 상품 조기 반환 유실은 수정했습니다.

## 선택적 웹 API

`python -m cv_store.web.app`은 로컬 주소에서 기존 `/sale`을 제공합니다.
`/test-db`는 기본 비활성화이며 로컬 진단 목적으로 `ENABLE_DB_DIAGNOSTICS=True`를 앱 설정에 지정해야 합니다.
인증·페이지네이션은 아직 없으므로 외부 서비스로 공개하기 전에 접근 정책을 정해야 합니다.
회원가입·홈 화면은 현재 앱의 URL에 연결하지 않았고 과거 시제품으로 보존했습니다.

## 검증 범위

오프라인 테스트는 존재하는 로컬 보존 파일의 해시, 합성 자료의 첫 행 보존, 실행 위치와 무관한 입력 경로,
임계값 경계, SQL 인자 바인딩, Slack 메시지·더보기, import 시 연결 방지,
적재 중복·충돌 처리, 증정 상품 누적 저장 회귀를 확인합니다.
실제 DB 타입·SQL 실행·Slack 전송·Tableau 갱신·사이트 크롤링 성공을 보증하지는 않습니다.
